# Testing

Standard interface (`npm test` and its variants are the same runner as `./scripts/test_runner.sh`, just invoked through `package.json`):

```
./scripts/test_runner.sh --smoke   # or: npm run test:smoke   — Pack Rat parser/fold/pool smoke tests (<5 s)
./scripts/test_runner.sh --fast    # or: npm run test:fast    — + the rest of the vault/config/build-core/optimizer-core [fast] tests
./scripts/test_runner.sh           # or: npm test             — + the [slow] exhaustive-search proofs, adapters/tazuo/test_paths.py and the Electron shell smoke test
```

Results land in `test_logs/latest_summary.json`. Read that, not the console output.

Everything runs on Node's built-in test runner (`node:test`); `scripts/test-runner.mjs` drives it with the programmatic `run()` API over every `app/*.test.mjs` and `scripts/*.test.mjs` file, then writes the summary.

## What is under test

- `app/gear-vault.test.mjs` — `app/vault-lib.mjs`: tooltip parsing (property keys, tags, STR requirement, rarity, extras/flags), name-to-slot classification, snapshot folding (newest scan of a root wins, skipped roots keep their last contents, tombstones), optimizer pool building (other characters' worn gear, STR gate, tag filter), requirement reports, the weapon-skill filter, `settingsDiff`, profile templates (`migrateProfiles` old → new shape and idempotence, `templateFrom` leaving race/STR out, drift via `settingsDiff`), saved-run keys and reuse (`runs-lib.mjs`), plus the optimizer core through the same loader the server uses: exact search against brute force (a hand-built case and 150 random suits), the other-suits list against every brute-force score (80 random suits), progress reporting, and warm starts. Fixtures: `app/fixtures/demo-*.json` (synthetic fixtures, see `app/fixtures/README.md`).
- `app/config.test.mjs` — `app/config.mjs`'s `resolveConfig`: the `--data`/`PACKRAT_DATA`/home precedence, the `--port`/`PACKRAT_PORT` precedence and validation, and `--demo`/`--open`. All `[smoke]`.
- `scripts/build-core.test.mjs` — `scripts/build-core.mjs`'s `buildCore()`: type-stripping produces a clean module, and it only rebuilds when the source is newer than the output.
- `scripts/optimizer-core.test.mjs` — the suit optimizer core (`scripts/optimizer-core.ts`), loaded through Node's native TypeScript type stripping. All `[fast]` — none of its cases use an exact/budgeted search.
- `app/mip.test.mjs` — `app/mip.mjs` (the pure MIP builder: columns, rows, hard/soft floors incl. the negative-total `u` column, the two-hander row, `startVector`/`pickedOf`/`noGoodRow`) and `app/mip-solve.mjs` (HiGHS solving a toy model exactly, the no-good cut finding the runner-up, `loadHighs` honoring `PACKRAT_NO_HIGHS`, and `gapFromEvents` — a pure unit test of the absolute-gap formula, plus an integration test on a deliberately large model that accepts either an `"optimal"` or a `"timeLimit"` outcome from a short time limit rather than assuming which way the clock falls). All `[fast]`, including the short real HiGHS solves.
- `app/solver.test.mjs` — `app/exact-solver.mjs`: HiGHS matches the core's proven optimum on every default template and the fixture inventory, soft floors and k-best alternatives agree with the core, an unreachable hard floor gets the core's partial credit, jointly-unreachable hard floors fall back honestly (`floorsConflict`), a negative soft-floor total scores zero credit like the core, HiGHS-unavailable (`PACKRAT_NO_HIGHS`) reports the heuristic result flagged `solver: "fallback"`, a plain timeout with and without an incumbent is reported honestly (never invented), and progress carries a bound during the exact phase. The one `[slow]` case generates a 3,000-item cell and checks HiGHS proves it and the core agrees wherever the core also proves it in budget — everything else is `[fast]`.
- `app/item-query.test.mjs` — `app/item-query.mjs` (the pure item-list filtering/sorting/paging/faceting shared by the browser and the server's `GET /api/items`): `parseItemQuery`'s defaults and clamping, every `applyItemQuery` filter (kind, slot, location, rarity, seenDays, slayer, nogarg, med, hideTags, a prop-column minimum incl. `EXTRA_COLS` keys) and sort (by prop column, by rarity ladder order), paging (offset/limit against `total`/`pieces`), group mode's JSON-safe shape, `facetsOf`, and `rarityRank`. All `[fast]`.
- `adapters/tazuo/test_paths.py` — the TazUO adapters' shared data-directory resolver (`packrat-paths.json` beside the script, else `PACKRAT_DATA`, else `~/.pack-rat`), matching `app/config.mjs`'s precedence. Runs under `python3` (or `python`, see below) in fast and full mode; skipped with a note if no Python 3 interpreter is on PATH. This is the one non-`node:test` piece — it's spawned as a subprocess by `scripts/test-runner.mjs`.
- `app/schema/validate.test.mjs` — `app/schema/validate.mjs`, the zero-dependency JSON Schema subset validator every scan, rules and profiles document is checked against: `type` (including array-of-types and the object/array/null edge cases), `required`, `properties`, `additionalProperties: false`, `items`, `enum`, `pattern`, `minimum`/`maximum`/`minLength`, unknown keywords ignored, nested paths (`/a/b/c`), array-index paths, and the 20-error cap on a single validation. All `[smoke]`/`[fast]`.
- `scripts/scrub.test.mjs` — the `[smoke]` guard described in `CONTRIBUTING.md`'s "The scrub guard" section: fails the suite if any tracked file carries the maintainer's identity or machine, the private workspace this project grew out of, a real in-game character name, the retired product name, or a non-placeholder `/Users/…` path. Runs over `git ls-files`, so it only sees what's actually tracked.

### The contracts layer (Phase 2)

Four files, together, keep the scan/bridge/rules contracts (`docs/scan-schema.md`, `docs/bridge-protocol.md`, `docs/shard-rules.md`) honest against the code that actually ships:

- `app/scan-schema.test.mjs` — `app/scan-schema.mjs`: `SCAN_V2_SCHEMA` is byte-identical to `app/schema/scan.v2.schema.json` (the two must never drift, since the `.mjs` copy is what gets served to the browser); `upgradeScan`'s v1→v2 conversion (naive-local `scannedAt` → RFC 3339 with this machine's DST-correct offset, `adapter` stamped — `"app"` for a `_`-prefixed tombstone character, `"tazuo"` otherwise — every root `opened: true`, every serial coerced to a number, `nameSource: "opl"` on every item/equipped entry); a v2 document passed through unchanged except a missing `shard` gets stamped; neither v1 nor v2 shaped throws; `validateScan` against the schema (including the fractional-seconds `scannedAt` shape `/api/forget` actually writes); `parseStamp` for fold ordering.
- `app/rules.test.mjs` — `app/rules.mjs`: both builtin rules files (`uoalive`, `generic-osi`) load and validate against `app/schema/rules.v1.schema.json`; `DEFAULT_SHARD`; `listRules` enumerates both builtins; a user rules file in a `userRulesDir` overrides a builtin of the same `id` (by the file's own `id` field, not its filename) and is reported with `source: "user"`; an invalid user rules file throws naming the file's path; `loadRules` throws naming the shard id when no matching file exists anywhere.
- `app/contracts.test.mjs` — walks every `adapters/<id>/` directory that ships both `capabilities.json` and `fixture.scan.json` (today: `adapters/tazuo/`) and checks, with no adapter-specific code: `capabilities.json` validates against the scan schema's `adapter.capabilities` shape; `fixture.scan.json` validates against the full `scan.v2.schema.json`; the fixture folds into a character with at least one nested container and at least one worn item located on it; and `capabilities.json`'s `capabilities` object is deep-equal to the fixture's own `adapter.capabilities` (catches a script's `CAPABILITIES` dict, its `capabilities.json`, and its fixture drifting apart from each other). A guard test fails the whole suite if no adapter directory ships a contract at all. Also covers `app/schema/bridge.v1.schema.json` directly: the documented command/result/status examples (including a `stopped: true` status) validate, and an unknown `action` is rejected. See `docs/adapter-guide.md` for what shipping a contract requires.
- `app/server.test.mjs` — HTTP route tests against a real listening server (ephemeral port, temp data directory): the CSP and `nosniff` header, no inline `<script>`, `/api/inventory` folding the demo fixtures, the `/ui/` allowlist (traversal and unlisted files rejected), `/schema/validate.mjs`'s own servability (a relative-import dependency of `scan-schema.mjs`), the 415 on a body with no declared content-type, `POST /api/forget` refused with 409 under `--demo` (so a demo session never writes a tombstone into the committed `app/fixtures/`), `readScans()` skipping an invalid or unparsable scan file without crashing the fold, the Host/Origin/token security checks (`--token` server), one running optimize job per client (a second `POST` supersedes the first), and the stack-free, ref-keyed 500 — both at the route level and from inside a failed optimize job (the job's real stack lands only in `<data>/logs/server.log`, keyed by the same ref the client sees). Also covers the Phase 4 routes added to the same server: `GET /api/setup`, `POST /api/setup/locate`, `POST /api/setup/install` (including the 409 running-script guard), `POST /api/import`, `GET /api/update-check`, `POST /api/host/pick-folder`/`open-path` (501 with no `host` given to `startServer`), `GET|PUT /api/settings`'s `setupDone`/`client` fields, and `GET /api/events` (the shared inbox SSE stream: `hello`, `inventory`, `rejected`).

### The desktop shell (Phase 4)

- `app/watcher.test.mjs` — `app/watcher.mjs`: `acceptedName`'s naming rule (slug + RFC 3339 stamp, collision suffixes), `ingestFile`'s normalise-then-move and idempotency (a doc already present in `scans/` under its accepted name is recognised and skipped, even across a simulated restart), and `startWatcher`'s debounce/retry/reject/`scanOnce`/`close` behavior against an injected fake `fs.watch`. All `[fast]`.
- `app/installer.test.mjs` — `app/installer.mjs`: `listAdapters` against the real `adapters/tazuo/` folder (copied into a temp dir, not a hand-built fixture), `candidateClientRoots`/`validateScriptsDir`'s folder-detection forms, `installedVersion`, `installScripts` (the running-script 409 guard, `.new`-then-rename, `packrat-paths.json` written last, a bad/traversal adapter id rejected), `importScans` (copy-only, symlinks skipped, existing names left alone), and `repoFromPackage`/`checkForUpdates` (every `package.json` `repository` shape, an injected `fetchImpl` — no real network in this file). All `[fast]`.
- `scripts/shell-smoke.test.mjs` — `[slow]`: launches the real `electron/` app (`electron . --smoke --demo --data <tmp>`) and asserts it boots, forks the server, loads the page over the token-bearing local server, and exits 0 with `SMOKE OK <port>` in stdout, within a 60 s harness timeout (the shell's own internal smoke check gives up after 30 s). Skipped with a note when `electron` isn't installed (a plain clone/CI box without the dev dependency) or when `TEST_SKIP_ELECTRON=1` is set — same shape as `TEST_SKIP_SLOW` for the other `[slow]` cases, for a machine where launching a real Electron binary isn't practical:

  ```
  TEST_SKIP_ELECTRON=1 npm test
  ```

- `scripts/ui-smoke.test.mjs` — `[slow]`: the Playwright-driven render check. Where the shell smoke test only proves the app boots and serves, this one drives the real Electron window (`electron . --demo --data <tmp>`, Playwright's `_electron.launch`) and proves the page itself renders: the title is "Pack Rat", `#status` finishes loading, the first-run wizard (a real `<dialog>` a fresh `--data` dir always opens) is dismissed the way a user would via its Skip button, the demo fixtures fill `#inv-table`'s rows rather than the empty state, clicking the Characters tab shows its panel, and nothing throws a `pageerror` along the way. Skipped, with the same note and the same `TEST_SKIP_ELECTRON=1` env var, when `electron` or `playwright` isn't installed — a plain clone/CI box without both dev dependencies.

  This is what stands in for a full end-to-end UI test today; `electron/README.md`'s "What's not exercised by the automated smoke test" section lists what still needs a human (the native folder dialog, Finder integration, a clean `Cmd+Q` with no orphaned `server-entry` process).

## Tags

Tags are prefixes on the test's own name, not a separate parameter: `test("[smoke] parseTooltip reads modeled props", () => { ... })`. The runner filters by `node:test`'s `testNamePatterns`:

- `--smoke` → only `[smoke]` (the handful that prove the pipeline is alive).
- `--fast` → `[smoke]` and `[fast]` (cheap; no brute-force or generated-cell proof, though `[fast]` now includes a handful of short real HiGHS solves — a few seconds each, not the exhaustive kind `[slow]` marks).
- full (no flag) → everything, `[slow]` included, plus the Python adapter test.

`[slow]` marks the exhaustive/exact-search proofs that run `optimizeSuit` with `exact: true` and a real `timeBudgetMs`, or the equivalent HiGHS proof on a large generated cell — the 150/80-random-suit brute-force comparisons and the demo-inventory exact/warm-start checks in `app/gear-vault.test.mjs`, and `app/solver.test.mjs`'s 3,000-item generated-cell case (HiGHS proves it; the core is checked against it wherever the core also proves it in budget). Set `TEST_SKIP_SLOW=1` to skip them (they register as `node:test` `skip` results, which the runner counts under `skipped`, not `passed`):

```
TEST_SKIP_SLOW=1 npm test
```

Add a tag to every new test; an untagged test only runs in full mode (no pattern is applied there).

## Ad-hoc runs

`node --test` works directly on this suite, but pass explicit file globs — bare directory names (`node --test app scripts`) do **not** recurse into subdirectories on this Node version/project layout, and running bare `node --test` with no path at all will additionally pick up `scripts/test-runner.mjs` itself as a test file (it matches Node's default `test-*.mjs` discovery pattern) and re-enter its own `run()` call. Use:

```
node --test 'app/*.test.mjs' 'scripts/*.test.mjs'   # every JS test, human-readable TAP output
node --test app/gear-vault.test.mjs                 # one file
node --test --test-name-pattern '^\[smoke\]' 'app/*.test.mjs' 'scripts/*.test.mjs'
```

## CI

`.github/workflows/ci.yml` runs the full suite (`npm test`, i.e. full mode, `[slow]` included) on every push and pull request, across a `macos-latest` / `windows-latest` / `ubuntu-latest` matrix, on Node 22 (the `engines` floor is `>=22.18`). It never sets `TEST_SKIP_ELECTRON` — the shell and UI smoke tests run for real on all three platforms rather than skipping, which on Linux means running the whole `npm test` invocation under `xvfb-run -a` so Electron has a virtual display to open a window on. Linux also gets a `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0` step ahead of the test run: `ubuntu-latest`'s AppArmor policy blocks unprivileged user-namespace creation, which is exactly what Chromium's sandbox falls back to when Electron is installed via npm (no root-owned SUID `chrome-sandbox` helper, since npm can't set that bit) — without it the Linux job's Electron launch fails or crashes immediately, display or no display. That step relaxes only the ephemeral CI VM's own kernel policy for the life of the job and deliberately keeps Chromium's sandbox itself enabled (`ELECTRON_DISABLE_SANDBOX` and `--no-sandbox` are never set, anywhere — `scripts/packaging.test.mjs` checks this directly, both in the workflow and in every shipped/test file), so CI proves the same sandboxed configuration a player runs, not a weakened one. The write is `|| true` so a future runner image that drops or renames the sysctl key can't fail the job outright, but a plain no-op would then leave the sandbox silently blocked with nothing in the log to explain a red Linux leg — so the step reads the value back afterward and emits a GitHub Actions `::warning::` annotation if the relaxation didn't actually take effect. The Python adapter scripts are also compiled (`python -m py_compile`) in the same job, ahead of the suite, as a second offline check beyond `adapters/tazuo/test_paths.py`. Each OS's `test_logs/latest_summary.json` is uploaded as a build artifact (`test-summary-<os>`) whether the job passes or fails, so a failure's detail is one click away instead of buried in console log.

`.github/workflows/release.yml` triggers on a `v*` tag push and runs `npm run dist:publish` on the same three-OS matrix, uploading unsigned installers to a draft GitHub release (`--publish always`, baked into the `dist:publish` script itself — see `package.json`). `CSC_IDENTITY_AUTO_DISCOVERY: "false"` keeps electron-builder from groping for a local signing identity that isn't there; no Apple ID, certificate or notarization secret is configured, matching the spec's v1 decision to ship unsigned and document the "damaged app" / SmartScreen workarounds instead (`README.md`).

## Not under automated test

The TazUO adapter scripts that run inside the game client (`packrat-scanner.py`, `packrat-refresh.py`, `packrat-bridge.py`) are verified live, attended. `python3 -m py_compile <file>` is the only offline check today.

Node ≥ 22.18 on PATH. The runner probes for `python3` first, then `python`, and uses whichever reports `Python 3` — needed for `adapters/tazuo/test_paths.py` in fast and full mode. To run that one file directly with warnings promoted to errors (the stricter check the gate before a phase closes uses): `python3 -W error adapters/tazuo/test_paths.py`. Full mode also needs `electron` installed (`npm i`, it's a `devDependencies` entry) for `scripts/shell-smoke.test.mjs`, and `electron` plus `playwright` for `scripts/ui-smoke.test.mjs`; without either dependency, or with `TEST_SKIP_ELECTRON=1`, that test is skipped rather than failed.
