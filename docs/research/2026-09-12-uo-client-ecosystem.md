# UO client and assistant ecosystem survey (Sep 12 2026)

Purpose: Gear Vault (`app/`) integrates with one client today, TazUO, through two Legion Script files: `scripts-legion/vault-scanner.py` (walks every equipped layer, the backpack, the open bank box and nearby ground containers recursively, dumps raw tooltip lines plus stats/skills/resists to a JSON file) and `scripts-legion/vault-bridge.py` (tails a JSONL queue, executes highlight / grab / goto by serial with pathfinding and container-chain opening, writes a status file). Before the app goes public we need a place and a system for other clients. This document surveys the 2026 ecosystem, scores each host against what the two scripts actually need, ranks what to build next, and proposes the adapter abstraction. Everything not marked as verified is labelled as such; the "What I could not verify" section at the end collects the gaps.

## What an integration needs (derived from the two scripts)

| # | Capability | Used by | Notes |
|---|---|---|---|
| A | Enumerate container contents, nested bags included, and open a container so its contents reach the client | scanner (`ItemsInContainer`, `UseObject`), bridge (`open_chain`) | Server only sends a container's contents after it is opened; nested chains need open + pause per level |
| B | Read an item's full tooltip / property lines (OPL) | scanner (`ItemNameAndProps`), bridge (name) | Raw lines, the app parses; must include engraving and negative tags |
| C | Read player stats, max pools, resists, skills with value + cap | scanner (`API.Player.*`, `GetSkill`) | Skills are ×10 on some hosts |
| D | Read every equipped layer, arms included | scanner (`FindLayer`) | The web client cannot read the arms layer |
| E | Know each item's serial, graphic, hue, amount and its container chain / root | scanner (`item_dict`, `scan_root`) | Serials are permanent per shard; the fold keys on them |
| F | Write a file, or make an HTTP request, from inside the script | scanner (`open()`), bridge (queue tail + status write) | Decides the transport: watched folder vs HTTP vs clipboard |
| G | Move an item to the backpack, pathfind to a tile/entity, show a local-only overhead message | bridge (`MoveItem`, `Pathfind*`, `HeadMsg`, `MarkTile`) | Overhead text MUST be local-only; public speech is a rules risk |
| H | Long-running loop with clean stop | bridge (`StopRequested`, `Pause`) | Needed for the bridge only |

## Per-host notes with citations

### TazUO (Legion Script) — shipping today

TazUO is a ClassicUO fork (BSD-2-Clause, last push 2026-09-11, rolling "TazUO-AutoBuild" release 2026-09-09) with an in-client scripting engine. The README lists "Custom build-in scripting — Python and Legion Script" plus built-in assistant features (auto buy/sell/loot) ([github.com/PlayTazUO/TazUO](https://github.com/PlayTazUO/TazUO)). The ".NET 10 (modern)" build is "available on Windows, Linux, and macOS with automated builds"; the ".net472 legacy" build is the older line ([tazuo.org/introduction/modern-vs-legacy](https://tazuo.org/introduction/modern-vs-legacy/)). C# scripting was merged into `dev` in Feb 2026 and shipped with the 5.0.0 rework (ImGui assistant UI replaced by Myra) ([discussion #395](https://github.com/PlayTazUO/TazUO/discussions/395)). The Python API doc is auto-generated (page dated 9/10/26) and every call is prefixed `API.` ([tazuo.org/legion/legionapi](https://tazuo.org/legion/legionapi/)); setup guide at [tazuo.org/wiki/legion-scripting-setup](https://tazuo.org/wiki/legion-scripting-setup/), feature overview at [tazuo.org/wiki/legion-scripting](https://tazuo.org/wiki/legion-scripting/).

Capabilities mapped to our needs, all from the API doc: `ItemsInContainer(container, recursive)`, `FindItem(serial)`, `FindType(graphic, container, range, hue, minamount)`, `ItemNameAndProps(serial, wait, timeout)` (name on line 1 then one property per line), `RequestOPLData(serials)`, `GetClilocString`, `GetSkill(name)` → `Value/Cap/Lock`, `FindLayer(layer, serial)` (reads every layer, arms included), `MoveItem(serial, dest, amt, x, y)`, `Pathfind(x, y, z, distance, wait, timeout, run)` / `PathfindEntity(...)`, `HeadMsg(message, serial, hue)` ("only visible to you"), `SysMsg`, `StopRequested`, `Pause`. File writes through Python's `open()` are proven by the scanner and bridge running live since Sep 10 2026; `subprocess.Popen` works, `subprocess.run` does not (project CLAUDE.md gotchas). The runtime is IronPython (the install ships `IronPython.dll`), so pure-Python stdlib works but C-extension packages do not.

The older "Legion Script" command language (UOSteam-flavoured `.lscript` files, the engine's original form before Python was added) still exists per the README; its dedicated wiki page returned 404 during this survey, so its exact command set is unverified. It is irrelevant for us: Python is the supported path and C# is the second.

Gear Vault status: scan = watched folder (`exports/scans/*.json`), bridge = JSONL queue + status file. This is the reference adapter.

### ClassicUO desktop — the plugin model

ClassicUO (BSD-2-Clause, last push 2026-09-08, "ClassicUO-main-release" tag 2025-11-04, Windows/Linux/macOS launchers) has no built-in scripting. Assistants attach as native plugins: "Download a compatible plugin with ClassicUO like Razor, RazorEnhanced, or ClassicAssist"; a plugin's DLL path goes into the launcher's plugin tab or the `plugins` list of `settings.json` ([wiki: Setup Plugins & Assistants](https://github.com/ClassicUO/ClassicUO/wiki/Setup-Plugins-&-Assistants), [ClassicAssist README](https://github.com/Reetus/ClassicAssist)). The plugin ABI is the `cuoapi.dll` delegate set with an `Install(void* ptr)` entry point (search summary; I did not read the header). Writing a Gear Vault plugin in C# directly against that ABI is possible but is a client-level project (packet hooks, world state), not a script — piggybacking on Razor Enhanced or ClassicAssist is the sane route. The README also states "Using a custom client to connect to official UO servers is strictly forbidden" ([README Legal](https://github.com/ClassicUO/ClassicUO)).

### ClassicUO Web client (play.classicuo.org)

Closed-source web build of ClassicUO running in WebAssembly, with a React "assistant" layer on top ([about](https://www.classicuo.org/about), [shard owners FAQ: will it be open source](https://www.classicuo.org/shard-owners/faq)). "Extensive support for automation using the built-in sandbox for executing visual programming scripts (Blockly) or more advanced code scripts (Typescript), however these can be disabled per the shards rules"; shards supporting the WebIdentity packet can verify a genuine client and "control exactly what features the web client is allowed to use" (same FAQ). It is the only third-party client sanctioned on official EA servers, "with features deemed unfair restricted" ([uo.com wiki](https://uo.com/wiki/classicuo-web-client/)). Settings, macros and scripts sync with the account across devices (search summary of the players FAQ).

Scripting API (globals `client`, `player`, `target`, `journal`, `worldMap` and the `Gump`, `Item`, `Mobile`, `Skill`, `PopupMenu`, `Prompt`, `IgnoreList` namespaces, [globals](https://www.classicuo.org/scripting/globals)): `client.queryItemOPL(serialOrObject, timeout)` returns `{serial, graphic, hue, amount, name, properties: [{id, text, values}]}` ([Client namespace](https://classicuo.org/scripting/namespaces/Client/)); `client.findAllOfType` / `findAllItemsOfType(graphic, hue, source, amount, range)`, `client.findItemOnLayer(serial, layer)`, `player.equippedItems` (slot-keyed map), `player.moveItem`, `player.equip`, `client.sysMsg` (local), `client.headMsg` ([Player](https://classicuo.org/scripting/namespaces/Player/), [Item](https://classicuo.org/scripting/namespaces/Item/)). Our live findings (project CLAUDE.md, Aug 2026): `.contents` populates without opening but throws on locked chests; the equipped arms layer is unreadable; `headMsg` is public speech; `findType` returns one non-nearest object per graphic; the sandbox kills sustained compute; `sleep` busy-waits; and there is no file, fetch, clipboard or download API — data left the sandbox by copying the script log. That last point is the whole transport story: a web adapter can scan (we already have `scripts/gear-scout.ts`) and must hand the JSON to the user through the log for a paste into the app.

Community reference: [malbolger/ClassicUO-WEB-Typescript](https://github.com/malbolger/ClassicUO-WEB-Typescript) (cloned under `reference/`), last push 2023-08-03, no license file.

### Razor Enhanced — UO Alive's bundled assistant

Derived from Razor, GPL-3.0, requires .NET Framework 4.8; v1.0.0.14 released 2026-07-16 (last push the same day). The project page says: "Currently the project is winding down as far as updates go. I'll still fix catastrophic bugs, but most of my time is on uo-copilot." It lists four script engines: IronPython, UOSteam syntax, Razor macro syntax, and C# compiled against the same API; the download line reads "supports OSI clients on Windows and Linux/Wine + CUO Windows Only Python 3.4 version" ([razorenhanced.github.io](https://razorenhanced.github.io/), [github.com/RazorEnhanced/RazorEnhanced](https://github.com/RazorEnhanced/RazorEnhanced)). A search summary claimed Linux and macOS builds exist "with less testing and only support the ClassicUO client" and that TazUO (.NET 10 and 4.7.2) is a supported host; I could not confirm either from a primary page.

API ([readthedocs](https://razorenhanced.readthedocs.io/)): `Items.FindAllByID(itemid, color, container, recursive)` where recursive is "True: all subcontainers, False: only main, 1,2,n: maximum depth"; `Items.FindBySerial`; `Items.GetPropStringList(serial)` → list of tooltip lines, `GetPropStringByIndex`, `GetPropValue` ([Items](https://razorenhanced.readthedocs.io/api/Items.html)); `Player.GetItemOnLayer(layer)` with layers "RightHand LeftHand Shoes Pants Shirt Head Gloves Ring Neck Hair Waist InnerTorso Bracelet FacialHair MiddleTorso Earrings Arms Cloak OuterTorso OuterLegs InnerLegs Talisman"; `Player.GetSkillValue` / `GetRealSkillValue(name)`; `Player.PathFindTo(x, y, z)` "using Client-provided pathfinding"; `Player.HeadMessage(color, msg)` "Visible only by the Player" ([Player](https://razorenhanced.readthedocs.io/api/Player.html)); `Items.Move(source, destination, amount, x, y)`; `Misc.SendMessage` ([Misc](https://razorenhanced.readthedocs.io/api/Misc.html)); a full A-Star `PathFinding` class with `GetPath`, `Go(Route)`, `RunPath` ([PathFinding](https://razorenhanced.readthedocs.io/api/PathFinding.html)). Contents of a closed container still need a double-click (`Items.UseItem`) and a wait, same as TazUO. File writes (source-verified Sep 12 2026 from a shallow clone of `RazorEnhanced/RazorEnhanced`): `Razor/RazorEnhanced/PythonEngine.cs` builds a stock IronPython 3.4.2 runtime (`Python.CreateRuntimeSetup`, search paths = Scripts, `Lib`, root) and injects only the RE modules into builtins; nothing removes `open`, `os` or `clr`, so plain Python `open(path, "w")` works anywhere on disk, and the community `ELoot.py` (ScriptB3ast/razor-enhanced) does exactly that (`open(self.File, 'w')`, plus `from System.IO import File, Directory`). The path/suffix restriction (RE or CUO directory tree, suffix in `.data .xml .map .csv`) lives only in `Misc.validateFilename` and applies to the `Misc.AppendToFile` / `AppendNotDupToFile` helpers, which we do not need. HTTP: `clr` gives `System.Net.WebClient` / `HttpWebRequest` from .NET Framework 4.8, so an HTTP POST adapter is also possible; not run by me. The repo also carries `Razor.Linux.sln` and `Makefile.linux` (Linux build under Mono is real); no macOS build files exist in the tree.

UO Alive: "Inside the package you will find the ClassicUO client, the launcher, and Razor Enhanced" ([uoalive.com/playnow](https://uoalive.com/playnow.html)). This makes RE the default host for most UO Alive players and therefore the first adapter to build.

### ClassicAssist — the active ClassicUO-only assistant

"Assistant for ClassicUO with UOSteam-like interface and macro syntax"; macros are Python with UOSteam-like function names; WPF, "only compatible with Windows"; an Avalonia port exists but needs contributors. GPL-3.0, 5.0.5 released 2026-08-16, last push 2026-08-21 ([github.com/Reetus/ClassicAssist](https://github.com/Reetus/ClassicAssist)). Macro commands ([wiki](https://github.com/Reetus/ClassicAssist/wiki/Macro-Commands)): Actions `Contents`, `WaitForContents`, `FindLayer`, `UseObject`, `ContextMenu`; Properties `Property`, `PropertyValue[T]`, `WaitForProperties` ([Properties](https://github.com/Reetus/ClassicAssist/wiki/Properties)); Entity `FindObject`, `FindType`, `CountType`, `Str/Dex/Int`, `Hits/Mana/Stamina`, `Graphic`, `Hue`, `Distance`, `DropItemToGround` ([Entity](https://github.com/Reetus/ClassicAssist/wiki/Entity)); Movement `Pathfind`, `Pathfinding`, `Walk`, `Run`; Messages `HeadMsg`, `Msg`. It also supports "Shared Variables" and can run alongside ClassicUO on the same machine as TazUO would. File I/O through IronPython is expected but unverified. Because RE and ClassicAssist are both IronPython, one Python scanner core with a small host shim could serve both.

### Razor (Community Edition)

"The goal of this project was to revive and continue development... while attempting to keep the spirit and vision the original developers had for Razor by not driving down the path of advanced automation and scripting that's found in other UO assistants" ([razorce.com](https://www.razorce.com/), [github.com/markdwags/Razor](https://github.com/markdwags/Razor)). GPL-3.0; last push 2025-03-07; last release "Razor-dev-preview" 2024-11-01; scripting engine since 1.6.4.2, command-based ([guide](https://www.razorce.com/guide/), [commands](https://www.razorce.com/guide/commands/)). Windows-first; Linux via Mono with ClassicUO ([Linux install](https://www.razorce.com/install/linux/)). The command reference has `findtype`, `lift`/`drop`, `overhead` (local), lists and variables, but no tooltip/property read and no file or network command. It also implements the UOAssist API (window messages for resource counts, skill level, logon) for external programs ([UOA API](https://www.razorce.com/uoaapi/)) — an interesting historical precedent for "an external app talks to the assistant", but it carries no item data. Verdict: cannot host a scan.

### Razor Enhanced vs Razor CE naming

"Razor" on razorce.com is Razor CE (markdwags). "Razor Enhanced" is the separate GPL fork with the Python API. UO Outlands ships its own fork of Razor CE ([UOOutlands/Razor](https://github.com/UOOutlands/Razor), last push 2022-05-02) with extra commands ([Outlands wiki](https://wiki.uooutlands.com/Razor_Scripting): `findlayer`, `getlabel`, `counttype`, `setvar`, lists, `ignore`).

### UOSteam

Closed-source, abandoned; the community calls it "the now deprecated UO Assistant, UOSteam" and warns it "is not allowed on every UO server" (search summaries of the her/uosteam and credzba repos; [uosteam.com FAQ](https://www.uosteam.com/uo-steam-faq/), [guide](https://www.uosteam.com/uo-steam-guide/)). Its command language (`findtype`, `contents`, `property`, `moveitem`, `headmsg`) has no file or network primitive. Razor Enhanced and ClassicAssist both emulate its syntax, so anyone still writing UOS macros has a migration path to a host we can support. Verdict: no adapter.

### Orion Assistant (OrionUO client)

OrionUO is an OpenGL UO client (MIT, [github.com/Hotride/OrionUO](https://github.com/Hotride/OrionUO), last push 2022-10-25); the Orion Assistant is a closed add-on with JavaScript scripting and a built-in Help documenting all functions; the site offers Windows x32/x64 and Linux x64 launchers ([orionuo.online](http://orionuo.online/)). Verified from the wiki: `Orion.FindType`/`FindTypeEx`, `Orion.OpenContainer(serial, delay, errorTextPattern)`, `Orion.MoveItem(serial, count, container, x, y, z)`, `Orion.SetCatchBag`, `Orion.GetSerial/GetGraphic`, `Orion.Exec`, `Orion.LoadScript(filePath)` ([Objects](https://github.com/Hotride/OrionUO/wiki/Objects-Orion-Assistant), [Interactions](https://github.com/Hotride/OrionUO/wiki/Interactions-with-other-scripts-Orion-Assistant)); `Orion.SkillValue`, `Player.Mana()`, `Orion.Print` from UO Alive community scripts ([UOAlive Orion Scripting thread](https://uoalive.com/forum/threads/orion-scripting.1215/), [starter guide](https://uoalive.com/forum/threads/orion-starter-guide.915/)). Tooltip/property reading and file writing are not confirmed by anything I could fetch; the assistant's in-app Help is the authoritative doc and is not on the web. UO Alive tolerates Orion (forum guides exist); Outlands bans it. Verdict: probe before promising anything.

### Stealth (standalone headless client)

"A client for Ultima Online that runs completely independently of the original UO client", scriptable in Pascal, Python and C#, "450+ methods", "behaves so close to the original client that the server can hardly tell the difference", built for running many characters ([about](https://stealth.od.ua/about/), [API index](https://stealth.od.ua/api/)). `GetTooltip(ObjID)` returns the tooltip as one string and requests it from the server if missing; `GetToolTipRec` gives structured cliloc ids + params ([GetTooltip](https://stealth.od.ua/api/GetTooltip/)); the index lists `GetSkillValue`, `GetSkillCap`, `GetStr/GetDex/GetInt`, `FindTypeEx`, `FindTypesArrayEx`, `MoveItem`, `ClientPrint`, `GetEquipment`, movement helpers. External Python via [py_stealth](https://github.com/ZeroDX255/py_stealth) (last push 2025-12-01) means a normal CPython process with full file/HTTP access — technically the easiest host of all. It is closed-source freeware, Windows only, and explicitly banned on Outlands; UO Alive's rules do not name it but it is a bot client by design. Verdict: do not build or advertise an adapter; accept a community one if it appears.

### UOAssist (Tugsoft)

Commercial, Windows, official client only. Still maintained: UOAssist.dll 1.22.15 on Jan 14 2026 and 1.22.14 on Dec 28 2025 ("can once again get the name/description of items") ([tugsoft.com/uoassist](https://www.tugsoft.com/uoassist)). No scripting; the UOA API is a set of Windows messages (resource counts, Magery level, logon) and cannot enumerate inventory. Verdict: no adapter.

### EasyUO / OpenEUO

easyuo.com refused connections during this survey. Search summaries describe a 2023 OpenEUO release that freezes the client on restart (reported Feb 2024) and a "badly broken" download page. Memory-reading tool for the official client, Windows only, banned on Outlands. Verdict: legacy, no adapter.

### AssistUO

### "CUO Assistant.NET"

I found no project by this name. The nearest matches are ClassicAssist (Reetus) and the web client's built-in "assistant" UI layer ([game profiles page](https://www.classicuo.org/features/game-profiles)). Treat the name as a misremembering of ClassicAssist unless someone produces a link.

### UO Outlands custom client

Outlands ships its own ClassicUO build with an integrated Razor CE fork; its Code of Conduct (last updated Aug 2 2026) allows only the Outlands Launcher, bans a long list of tools (UO Steam, EasyUO, AssistUO, RazorEnhanced, ClassicAssist, Stealth, MobileUO, Orion, AutoHotkey, mappers...), and states that "any method of automation or programmatic data extraction from the game client is not allowed" ([uooutlands.com/rules](https://uooutlands.com/rules/); the tool list and the quoted sentence were re-read from the live page on Sep 12 2026, which also names the only staff-sanctioned third-party tools, ExploreOutlands, Outlands Butler and LootGoblin, and says even data "made accessible via the official client and Razor assistant" must be "acted upon manually by the player"). Unattended skill gain is allowed there, unattended resource gathering is not. Verdict: a Gear Vault scanner would violate Outlands' rules regardless of feasibility; the only Outlands-compatible path is manual entry.

Official clients; EC has a drag-and-drop macro bar, CC a macro editor; neither exposes a scripting language or a data export. UO Alive offers an EC package with the warning "OSI no longer supports this client. It may crash in certain areas" ([uoalive.com/playnow](https://uoalive.com/playnow.html)). Unity-based mobile client derived from ClassicUO; the UO Alive community build (Mandlar) is v1.0.31 (2026-08-21) ([github.com/MobileUO/MobileUO](https://github.com/MobileUO/MobileUO), [uoalive.com/playnow](https://uoalive.com/playnow.html)); "uses the CUO client with no 3rd party assistant, and scripting is not possible" (search summary). ## Licensing constraints on shipping our scripts

Not legal advice; this is what the licenses say and how the ecosystem treats scripts.

- TazUO and ClassicUO are BSD-2-Clause; the Razor Enhanced, ClassicAssist, Razor CE and Outlands Razor assistants are GPL-3.0; TazUO's `PublicLegionScripts` repo is GPL-3.0; Orion Assistant, Stealth, UOSteam, UOAssist, AssistUO and the ClassicUO Web client are closed source (GitHub API metadata fetched Sep 13 2026; [RE site](https://razorenhanced.github.io/); [CUO FAQ](https://www.classicuo.org/shard-owners/faq)).
- Our scanner/bridge files are separate programs that call a host's scripting API at run time, the same way every community script in `her/uosteam`, `PublicLegionScripts` or `orion-uo-scripts` does. They are not linked into the GPL binaries and do not copy their code, so the GPL does not propagate to them under the usual reading; we can publish them under the app's own license (MIT or Apache-2.0 both fine).
- Two things would change that: (1) redistributing a GPL assistant's binaries inside our download (then we owe GPL compliance for that binary: license text, source offer) — do not bundle hosts, link to their installers; (2) copying code from `PublicLegionScripts` (GPL-3.0) into our scripts — do not; write from the API docs, as the current scripts already are. The `reference/PublicLegionScripts` clone is fine to read for idioms.
- Closed-source hosts (Orion, Stealth, UOSteam) have no redistribution problem for scripts either, but Stealth's terms are unknown to me; another reason not to ship a Stealth adapter officially.
- The ClassicUO Web sandbox has no license text for user scripts that I could find; a TypeScript scanner we publish is ours.

## Ranked list: which integrations to build next

1. **Razor Enhanced (Python) — build first.** It is inside UO Alive's All-in-One package, so it is what the majority of the app's first users run. The API covers every need with near one-to-one calls (`Items.FindAllByID` recursive, `Items.GetPropStringList`, `Player.GetItemOnLayer("Arms")`, `Player.GetSkillValue`, `Items.Move`, `Player.PathFindTo`, `Player.HeadMessage` local-only) and the transport is the same watched folder TazUO uses. Risks: the maintainer says the project is winding down (API is stable, so low risk) and it is Windows-first (Linux under Mono exists, no macOS). File writes are verified from source (stock IronPython 3.4.2, plain `open()`), so the first task is the real scanner, with a five-line probe that writes `exports/probe-re.json` only as the install smoke test; the one path detail to handle is that when RE runs as a ClassicUO plugin its working directory is the CUO folder (`Misc.CurrentScriptDirectory()` / `Assistant.Engine.RootPath` give the real locations), so resolve the output folder from the user's home, never relative.
2. **ClassicUO Web (TypeScript) — build second, scan only.** UO Alive's other recommended client and the only cross-platform browser option; we already have `scripts/gear-scout.ts` and the parsing gotchas. Transport must be clipboard/paste: the script prints a single-line JSON blob with a marker, the user copies it from the script log into an Import box (or drops the saved `.txt`). Limits to state in the UI: arms layer reported as "unreadable", `headMsg` never used (public), no walk-to, bank unreadable. Its value is also the fallback for players on official shards if the sandbox keeps `queryItemOPL`.
3. **ClassicAssist (Python) — third, shares the RE core.** Active (5.0.5, Aug 2026), same IronPython, UOSteam-like names (`Contents`, `Property`, `FindLayer`, `Pathfind`, `HeadMsg`). Windows only. Worth doing as a thin shim over a shared Python scanner core once RE is proven, because the two together cover every desktop ClassicUO player who is not on TazUO.
4. **TazUO C# scripting — optional, same host.** Only if TazUO deprecates the Python engine; otherwise no user gain.
5. **Orion (JavaScript) — probe only.** Windows/Linux, tolerated on UO Alive, but tooltip reading and file writes are unverified and the docs live inside the app. Write a probe script and decide after.
6. **Stealth — do not ship.** Technically trivial (external CPython, `GetTooltip`, `GetToolTipRec`), but it is a bot client banned on major shards and would taint the app's "attended, inventory-only" positioning.
7. **Not viable, document as manual-import:** Razor CE, Outlands Razor, UOSteam, UOAssist, EasyUO/OpenEUO, AssistUO, EA Enhanced/Classic clients, MobileUO. For Outlands the rules forbid extraction outright.

## Recommended abstraction: adapters over a versioned scan contract

The app should own one contract and treat every client as an adapter that produces it. Three pieces: the scan schema, the bridge protocol, and the transport.

### 1. Scan schema (the contract) — bump to `version: 2`

Today's file is `{version: 1, character, scannedAt, stats, position, maxes, resists, skills, equipped[], roots[], containers{}, items[]}` with raw `lines[]` per item and the fold rule "a scan replaces everything under each root it lists" (`app/CLAUDE.md`, Data model). Keep all of that and add:

- `schemaVersion: 2` and an `adapter` block: `{id: "tazuo-legion" | "razor-enhanced" | "classicassist" | "cuo-web" | "orion" | "manual", version: "x.y", client: "TazUO 5.x", host: "...", capabilities: {arms: true|false, bank: true|false, ground: true|false, bridge: ["highlight","grab","goto"]}}` so the fold and the UI can show "arms unreadable on this scan" instead of guessing.
- `shard: "UO Alive"` (serials are per shard; the fold must never merge two shards) and `account` (optional, hashed) for the multi-account case that Sable already created.
- Per item, keep `serial, graphic, hue, amount, lines[], container, root, layer` and add `nameSource: "opl" | "label"` so hosts that only give a single-click label (Razor CE style) can still contribute degraded records the parser knows to distrust.
- `roots[]` entries gain `opened: true|false` so "not opened, skipped" is recorded rather than omitted; the fold keeps the existing rule (unopened root = keep old contents).
- Reserve `meta` for adapter-private data (already ignored by the fold).

Write the schema as `app/schema/scan.v2.schema.json` (JSON Schema), validate on ingest, and accept v1 files forever by upgrading them in `foldSnapshots`.

### 2. Bridge protocol — same shape for every host

Command: `{id, action: "highlight" | "grab" | "goto", serial, name, chain: [root … parent], pos: {x,y,z} | null}`; result: `{id, ok, msg}`; status: `{alive, character, adapter, current, results, counts}`. Hosts declare which actions they support in `adapter.capabilities.bridge`; the page greys out the rest. The web client adapter would support only `highlight` (as a `sysMsg` with the container chain spelled out) and `grab` (`moveItem` when in range), never `goto`.

### 3. Transports — three, chosen per adapter

- **Watched folder (current).** Adapter writes `exports/scans/<char>-<stamp>.json`; the server already folds on request. Add `exports/inbox/` as the public drop location with one sub-folder per adapter and a small `fs.watch` so a fresh scan appears without a reload. Bridge = `exports/bridge/queue.jsonl` + `status.json`, as today. Hosts: TazUO, Razor Enhanced, ClassicAssist, (Orion/Stealth if file writes exist).
- **HTTP to localhost.** `POST /api/scan` (body = scan JSON), `GET /api/bridge/next?adapter=...` (long-poll, returns one command), `POST /api/bridge/result`, `POST /api/bridge/heartbeat`. Same server, same fold. Useful for hosts whose scripting runtime has an HTTP client but an awkward filesystem (external Python, any C# script with `HttpClient`, a future CUO plugin) and for running the app on a different machine than the game. Bind to 127.0.0.1 by default; a shared token in the adapter config if it is ever exposed on the LAN.
- **Clipboard / manual import.** An Import tab with a paste box and a file picker that accepts the same v2 JSON (and a compact single-line form the web script prints to its log with `GEARVAULT:` markers). Hosts: ClassicUO Web, and the "manual" adapter for players on clients with no scripting at all (a small form to type an item's tooltip lines; produces a v2 scan with `adapter.id: "manual"`).

### 4. Repository layout

`adapters/<id>/` with the script(s), a `README.md` (install path, how to run, what the host cannot do), a `capabilities.json` that mirrors the `adapter.capabilities` block, and a fixture scan under `app/fixtures/` so `gear-vault.test.mjs` proves the fold handles that adapter's quirks (arms missing, label-only names, no bank). Move `scripts-legion/vault-scanner.py` and `vault-bridge.py` to `adapters/tazuo-legion/` with a shim left in `scripts-legion/` until the TazUO live copy is redeployed via the `-stopall` protocol. The parser stays host-agnostic: raw lines in, structured props out, exactly as now.
