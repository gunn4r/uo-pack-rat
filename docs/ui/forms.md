# Forms: the Import drawer, the setup wizard and Settings

Part of the UI docs: [`docs/ui.md`](../ui.md) has the hard rules, tokens, components and the dependency rules every screen follows.

- **Import drawer** (`ui/import.mts`). A pasted scan or a scan file is parsed in the page by `app/paste-scan.mts` — the same `parsePastedScan` POST `/api/import/paste` runs, browser-safe and served at `/paste-scan.mjs` — so the preview can never call clean what the server then refuses. Scan files (dropped anywhere on the window, or a chosen folder) are read in the page and sent through that same paste route one by one, so every file gets the same preview. The preview card's counts and the primary button's sentence come from the DOM-free `ui/import-preview.mts`. A re-render never drops focus out of the open drawer (Esc and the focus trap listen inside it).
- **Client wording** (`ui/adapter-copy.mts`). Everything the page says about a game client — short names, the wizard's client cards, per-step questions and help, the Import drawer's client options, the wizard's step names — is written per adapter there, never assembled from an adapter's README title. An adapter the table doesn't know still gets plain text from its own name and summary; a new shipped adapter should get its own entry.
- **Wizard** (`ui/wizard.mts`, a `.dialog`). One primary per step (`#wiz-primary`), which ↵ runs; the paste branch renames steps 3 and 4 as soon as a paste client is picked. Step 3's typed path lives in the wizard's state, so it survives a failed "Use this path". The step 1 shard pick is held the same way and applied by Finish (the PUT and page reload of `ui/shard.mts`), so changing it keeps the wizard open, and Set up later or Esc leave the saved shard as it was.
- **Update notice** (`#update-notice`, `ui/settings.mts`'s `startUpdateChecks`): with Check automatically on (the default; settings `autoUpdateCheck`), the page calls `GET /api/update-check` 5 s after load and every 6 hours; a newer release shows one line above the screen with View release and Dismiss, which saves that version as the ui-prefs `dismissedUpdate` so only a later release shows again. It only tells: nothing is downloaded.
- **Data-folder banner** (`#notice`, `ui/bridge.mts`'s `renderDataDirNotice`): one short line above every screen, "Show details" (Settings › Data, where the full sentence with both paths stays) and Dismiss. It takes its own height in `.main`'s column and the screen below (flex 1, min-height 0) shrinks to fit; `.shell`'s one grid row is pinned to the window.
- **Settings** (`ui/settings.mts`). Five sections — General (Theme, Appearance, Shard rules), Game client (the client's status, Run setup, Reinstall, and for TazUO the in-game panel card: show at login and its hotkey, `ui/tazuo-panel.mts`'s `panelControls`, which the wizard's install step shows too), Data (the data and logs folders, Blacklisted containers, export and import of the player's item kinds, Data retention with Clean up now, the danger zone), AI assistants (MCP) (the built-in MCP server's two switches and how to connect a client, issue #211) and Updates (the version, Check for updates, Check automatically) — at the page's full width, like every other screen, with no section nav (the page is short; bring one back if it grows); a section that needs attention carries a warning dot beside its heading (Game client with no client set up). Setting rows are `.set-row` (title and help left, control right, anything spanning below in `.set-row-below`). The Theme select lists every theme family and enables one once its id is in `ui/theme.mts`'s `BUILT_THEMES`; a choice applies at once and is saved with the other ui-prefs. The data-folder mismatch (`dataDirNotice`) shows in the Data card as well as the banner; each folder row has Open in the desktop app and Copy path in a plain browser (`GET /api/setup`'s `canOpenFolders`, true only when the desktop shell can open a folder), and the danger zone's character list follows the inventory (`syncSettingsCharacters`, run on every `inventorychange`). With the ClassicUO web client chosen, Game client has a Scanner script row whose Copy scanner script button (`ui/paste-scanner.mts`, shared with the wizard's step 3) copies the app's bundled scanner from `GET /api/setup/scanner`, and says when that version is newer than the one last copied (ui-prefs `copiedScanner`). The Data section's Blacklisted containers card (Unblacklist per row) is fetched again on every visit to Settings (`syncSettingsBlacklist`), since the in-game script writes the list too.
