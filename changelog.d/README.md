# Changelog fragments

Each pull request that matters to a player or a contributor adds one file here, `changelog.d/<short-name>.md` (lower case, hyphens or underscores: the branch name with `/` replaced by `-`, starting with the issue number and a hyphen, so `338-changelog-fragments.md`; `scripts/changelog.test.mts` checks the prefix), instead of editing `CHANGELOG.md`. The file holds one or more entries in `CHANGELOG.md`'s style, one line each, every line starting with `- `. At release, `node scripts/changelog.mts --release <version>` puts the fragments together into `CHANGELOG.md`, newest first by the issue number the name starts with, and deletes them (`RELEASING.md`). Player-facing entries come first; an entry for contributors starts its title with `For contributors: ` and is released under a `### For contributors` subheading, without that prefix. `_highlights.md` is not a fragment: it is the release's short summary, written when the release is cut (`RELEASING.md`). `node scripts/changelog.mts` prints what the next release would say, and `scripts/changelog.test.mts` checks every fragment's shape.
