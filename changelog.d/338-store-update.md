- **For contributors: read-modify-writes go through `store.update(fn)`** (issue #338): the blacklist, house claims and Organize state stores have `update(fn)`, which reads the file, hands a synchronous function the contents read-only and writes what it returns, with no await in between, so no other change can land in the gap and be lost. The blacklist and house-claims routes, Grab and Organize's trip bookkeeping use it, and the rule is written in `app/store/json-file.mts` and `docs/change-checklists.md`. A Move to trip queued after the inventory was reloaded no longer writes back the Organize state it read before that wait, so a Grab or a finished trip recorded in between is kept, and a second trip planned from the same read is refused while the first has not reported back.
