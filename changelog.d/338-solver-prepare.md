- **For contributors: everything before the search in one function** (issue #338): `prepareSolve` in `app/solver/prepare.mts` makes every change to a build's input (tie costs, search defaults, reachable resist steps, the SSI step table, the hard-floor bonus) and computes the run key and pre-build diagnostics, in one fixed order. `POST /api/optimize` calls it. The step table now travels with the job, so the worker no longer works it out a second time. Run keys and results are unchanged.
