# Changelog

## Unreleased

### Security

An adversarial review went over the app in seven areas — the local server, the scan and bridge parsers, the script installer, the Electron shell, the adapter scripts, the supply chain, and the privacy claims themselves — and everything below came out of it. `docs/threat-model.md` is new and is the long form: what each boundary is holding, which defence is load-bearing against which attack, and the handful of findings deliberately left standing with the reason for each.

- **Adapter scripts now distrust their own command queue — re-install them.** `<data>/bridge/<client>/queue.jsonl` is an ordinary file that drives your character in a live game, and anything on your machine can write it, so the bridge no longer assumes the app validated a line before acting on it. It refuses a command older than 60 seconds or one it has already run, opens nothing that is not really a container (corpses included) and no chain longer than 8, refuses a walk further than 24 tiles or off the map, and grabs only from your own backpack, your bank, or the container that same command just opened — the destination was always your own backpack and still is. If the queue is written faster than a person clicks, the bridge says so and stops, because at that rate something other than you is writing it. One junk line no longer swallows the rest of a batch, and neither the client nor the status file can be made to grow without bound. **TazUO scripts are now 2.1.0 and Razor Enhanced's 1.1.0: re-install them from the app's Settings tab (Reinstall) or re-run the setup wizard.** These limits have not yet been exercised against a live client — the threat model lists which assumptions would fail first, and a false refusal reports itself in game and on the page.
- **A shared scan file can no longer do anything to the app but be read.** Scans get passed around, so one is treated as a stranger's text end to end: the character sheet and item tooltip are built from DOM nodes with no markup path left anywhere in the page, the schema types and bounds every field instead of leaving whole sections unchecked, the fold and the tooltip parser no longer have shapes whose cost grows with the square of what a file contains, and a file over 32 MB — or one that is a symlink rather than a real file — is refused in the inbox before it is read. A file that fails to parse now says so without quoting its own contents back at you.
- **Every request the local server accepts is checked field by field.** A body that is not a JSON object is refused rather than becoming an internal error; the routes that write files validate what they are about to write; a build request's options are an allowlist with real ranges; at most four builds run at once; the page cannot be put in a frame by another site; requests time out; and the data directory and the files in it are created readable only by you.
- **The installer cannot be redirected out of the folder you picked.** Game clients arrive as unpacked archives, and an archive can contain symlinks. Every file the installer and the scan importer write now goes through one helper that refuses any destination that is not either absent or an ordinary file, and writes through an unpredictable temporary name. A `packrat-paths.json` you wrote by hand, pointing at a different data directory, is now kept instead of silently overwritten.
- **The desktop shell gives less away.** Electron's spellchecker is switched off, so on Windows and Linux the app no longer downloads a dictionary from Google's servers the first time you click into a text box — which `PRIVACY.md` had always said could not happen. The window denies every permission request (camera, microphone, location, clipboard), refuses to navigate anywhere but its own page, and hands only an `https:` link to your normal browser. Packaged builds turn off the Electron fuses that would let the installed program be re-used as a general-purpose script interpreter, keep the app's own code inside the archive rather than as loose files beside it, and ship with developer tools off. "Check for updates" now ignores the link in GitHub's own answer unless it really points at this project's releases.
- **The release path was split so that the job running three hundred build dependencies holds no token.** Building and publishing are separate jobs now: the build matrix has read-only access and no release token at all, and a separate job with no checkout and no dependencies uploads the installers plus a `SHA256SUMS` file you can check a download against (`README.md` and `RELEASING.md` have the command). Every GitHub Action is pinned to an exact commit rather than a movable tag, both workflows install without running package lifecycle scripts, and Dependabot now watches npm and the action pins.
- **The privacy document was corrected where it was wrong.** It overstated two of the server's checks, understated what the data directory holds and what the logs contain, and — the one that mattered — described a scan file as identifying "which character and account it came from" without mentioning that it also carries your full skill and stat profile and the **world coordinates of your character and of every container scanned**, which in practice is your house. `PRIVACY.md` now says all of that plainly, with a warning to look at a scan file before attaching it to a public issue. `SECURITY.md` no longer sends reporters down the public route on the strength of a stale hedge — private vulnerability reporting is on.
- **The bridge only opens containers that lead down from your own root — re-install the scripts (TazUO 2.2.0, Razor Enhanced 1.2.0).** A queue line could name another player's backpack in its container chain, and the bridge would double-click it — a snoop attempt the victim is told about. Each container in a chain is now checked against the live client just before it opens: the first must lie on the ground or be your own backpack or open bank box, and each after it must sit inside the one before. A refused command now shows its reason on the button you clicked, instead of only in game.

### Everything else

- **The exact suit builder no longer calls a worse suit "proven optimal".** When a soft-floored property could total below zero, the model ruled out every such suit, so HiGHS could certify a worse one, or report a floors conflict for a profile with no hard floors. A negative weight on a capped property (most properties carry a shard cap) now builds an exact model instead of failing the job with an internal error. The time budget covers the whole job (the heuristic's restarts, every HiGHS call and the alternatives), saved runs from before this fix are no longer reused, and a fallback result (HiGHS unavailable, or the floors-conflict retry out of time) is never reused. A seeded brute-force test over 2,000 small inventories now guards all three searches.
- The test runner can no longer report green for tests that did not run: a test file that exits part-way (even with code 0) is a failure, a type or build error before the tests is written to `test_logs/latest_summary.json` as a failure instead of leaving the last summary in place, a run where no test ran fails, and every test has a timeout. `npm run dist:dir` builds the page first, `npm run dist:publish` is gone (the release workflow's publish job is the only uploader), and a crashed server child in the desktop app is restarted each time unless it is crash-looping, rather than once per launch.
- Fixed scans that could silently erase inventory records. The app replaces everything it knew under a container with the newest scan of it, so a container written as "opened, nothing inside" when it never opened wiped its contents: TazUO when Stop was pressed while the last chest opened, Razor Enhanced for any chest that timed out (locked, out of reach, a slow server), both for a bag inside a chest that did not open, and the ClassicUO web scanner for an unloaded ground chest. A chest that did not open is now left unrecorded so the app keeps what it knew; a bag inside a chest that did not open (or sits too deep to read) is marked not opened, and the app keeps what it knew inside that bag while the rest of the chest updates. A deed, a bag of sending or a music box is never double-clicked. A stopped TazUO scan writes nothing, and the web scanner no longer turns every item into a container on a build that gives items an empty contents list. Razor Enhanced scans now name skills the way the game does, so the Resisting Spells resist bonus is no longer 0 for those characters. The bridges keep their status fresh during a Highlight or a walk, so the page no longer calls the bridge offline and refuses clicks mid-command, and a Highlight or Grab of something in your own backpack or bank no longer fails trying to walk to it. The ClassicUO web scanner is now 1.1.0. The TazUO and Razor Enhanced scripts no longer stop at start if the client runs them without defining `__file__` (TazUO then finds its settings file through `API.ScriptPath`).
- Migrated every source and test file to TypeScript (Phase 8): sources are now `.mts` and import each other by their real extension (`./x.mts`), which Node and Electron run directly through native type stripping with no build step for the server, the tests, the worker threads or the Electron main/utility processes; only erasable TypeScript is allowed (`erasableSyntaxOnly` — no `enum`, `namespace`, parameter properties) since anything else would fail at run time. The one compile step left is the page (`npm run build:ui`, `scripts/build-ui.mts` → `tsc -p tsconfig.browser.json` → `app/dist/`), which exists only because a browser cannot strip types, and which every `pre*` hook, `scripts/start.mts`, `scripts/test-runner.mts`, `app/server.test.mts` and (in development) `electron/main.mts` run for you; `npm run typecheck` is what CI enforces on macOS, Windows and Linux. `app/schema/types.d.mts` is generated from the JSON Schemas by `npm run build:types` — the schemas stay the authority, and a shape change is made there, never in the generated file. Retired `scripts/build-core.mjs` and its git-ignored `app/dist/optimizer-core.mjs` output along with it: the optimizer core is a `.mts` file Node (and the packaged app, out of `app.asar`) now runs straight from source. `tsconfig.json`'s `allowJs`/`checkJs` scaffolding, kept during the migration so an as-yet-unconverted `.mjs` file could still resolve, is gone now that nothing needs it. No runtime dependency changed; `dependencies` still names only `highs`.
- Fixed a tooltip-parsing bug (found auditing the owner's real scans) where a negative standard property immediately followed by its digits — "Faster Casting -1" was the one real example, the only negative standard property across 24 scans/212 lines — parsed as positive and scored as a gain instead of a loss: `parseTooltip`'s property regexes skipped everything before the digits with `\D*`, which happily swallows a minus sign too. The skip class is now `[^-\d]*` with a `-?\d+` capture, so a minus sign counts only when it sits immediately against the digits; a dash-separated range ("Weapon Damage 13 - 16") and a spaced-off stray dash are both unaffected. Every other numeric-property site (totals, requirement reports, item filtering/sorting, the optimizer's own truthy checks, the MIP model) already handled a negative correctly.
- **The suit builder now gets the right item data** (issue #15). A set piece's full-set bonus (the lines after "Only When Full Set Is Present:") is no longer added to the piece's own properties, which had credited every Armor Of Initiation piece with +20 resist points it only earns with the whole set on; the bonus is kept separately as `setBonus`. An unequipped piece now goes to the slot its graphic belongs to in the client's tiledata, so named artifacts ("Heart Of The Lion"), set pieces all named "Armor", "... Arms", skirts, pants, hakama, quivers and "Gold Ring" reach the builder in the right slot instead of the chest slot or none. Middle-torso clothing (a doublet) has its own slot instead of competing with chest armour. A scan whose `scannedAt` is not a real date and time is refused instead of scrambling the fold's order, and a shard rules file whose caps, tag units or breakpoints are not numbers is refused.
- Fixed Save as… doing nothing in the desktop app: the suit builder's Save as… called `window.prompt()`, which Electron does not implement — it silently returns `null`, so the handler bailed before anything happened, unnoticed because it worked fine in a plain browser. Replaced it with an in-page `<dialog>` (`ui/dialog.mts`'s `promptText()`) styled to match the setup wizard's dialog.
- Fixed the suit builder's Highlight/Grab/Go-to bridge buttons vanishing for a player who pressed Skip in the setup wizard or installed an adapter's scripts by hand: the server already fell back to a routing default (`tazuo`) for those `settings.client`-unset requests, but the page's own visibility check didn't know that, so it hid every bridge button even though the bridge itself was working. `GET /api/setup` now reports that same routing id, and the page falls back to it too, with a note telling the player they're running against the assumed default rather than a client they configured.
- Fixed the MIP suit-search's floor-reach estimate treating a required slot as though leaving it empty (contributing 0) were always a legal option — only true for an optional slot. A required slot whose every real candidate is negative in a floored dimension could never actually reach 0, so the estimate could overstate what a suit can reach and let a genuinely-unreachable hard floor through as a real constraint, with the mistake only surfacing as HiGHS reporting the whole model infeasible and a wasted retry. The reach estimate now shares the same required/optional check the slot-row constraint already computes.
- Fixed the Import tab rendering a stray literal "null" after the Rescan panel before any scan had been pasted, imported or rescanned — a conditional `null` passed straight into `replaceChildren()` doesn't get skipped the way it does inside the page's own `el()` helper. Added `compactChildren()` (`ui/dom.mts`) to filter `null`/`undefined` out of a children array first, matching the pattern the builder and saved-runs panels already used.
- Made `make-adapter-fixture`, the maintainer tool that turns a real scan into a committed `adapters/<id>/fixture.scan.json`, validate both the scan it reads and the fixture it's about to write, instead of trusting an unvalidated cast on the way in — it's about to be pointed at the first real scans from two adapters that have never run against a live client, which is exactly when a malformed scan is most likely, and failing here with the schema error is kinder than a fixture that only fails later in `app/contracts.test.mts`. Fixing this also surfaced a latent bug at the call site: an omitted `shard` option was landing as an explicit `undefined` rather than `null`, which fails the schema's string-or-null check even on an otherwise-valid v1 document.

- Made the game-client bridge per adapter (`app/config.mjs`'s `bridgeFor`/`bridgeQueueFor`/`bridgeStatusFor`, mirroring the existing per-adapter inbox): `POST /api/bridge`, `GET /api/bridge/status`, and `POST /api/setup/install`'s running-script guard used to be hard-coded to `<data>/bridge/tazuo/` regardless of which client was actually configured, so a Razor Enhanced player's fully-capable Highlight/Grab/Go-to buttons queued commands into a folder that adapter's own `packrat-bridge.py` never reads — a silent no-op. The bridge queue/status routes now resolve the directory live off `settings.client.adapter` (falling back to `tazuo` only when no client is configured, matching the previous behavior for that case); the install guard checks the adapter actually being installed, not necessarily the configured one. Neither adapter script needed to change — each already read/wrote its own `bridge/<its-own-id>/` directory. No data migration for an existing TazUO player: `bridgeFor("tazuo")` is byte-identical to the path the app always used. `docs/bridge-protocol.md`, `docs/architecture.md` and `CONTRIBUTING.md` updated to match.
- Fixed two edge cases in the ClassicUO web scanner's chunked print loop (`adapters/classicuo-web/packrat-scanner.ts`): a chunk boundary could split a UTF-16 surrogate pair (an astral character, e.g. an emoji in an engraved item name), corrupting it on any copy/paste path that doesn't preserve a lone surrogate byte-for-byte — `chunkEnd()` now backs the boundary off by one whenever it would land inside a pair. U+2028/U+2029 (LINE/PARAGRAPH SEPARATOR), unlike `\r`/`\n`, are valid *unescaped* characters inside a JSON string, so a console that treats either as a line break on render or copy could turn it into a real newline that the receiving side's own newline-stripping would then delete — both are now escaped explicitly before printing. Also added a real parse check for `packrat-scanner.ts` (`app/classicuo-web-adapter.test.mjs` now spawns Node's own TypeScript type-stripping directly against the file) after a source-corruption bug — a literal `\u` escape sequence typed next to raw hex digits silently became the actual separator character during an editing pass — shipped through every existing test undetected, since none of them had ever actually parsed the file as code.

- Replaced the exact search's multi-thread branch-and-bound (a worker pool splitting the tree into tasks over a shared best-score counter, `app/shared-search.mjs`) with [HiGHS](https://highs.dev/) (the `highs` npm package, MIT, compiled to WebAssembly) — the one runtime dependency this app now has. `app/mip.mjs` is the pure MIP builder (one binary per slot/item pair, capped weighted properties as a concave column, hard floors as a row plus a constant bonus, soft floors as indicator + partial-credit columns with a relaxing `u` column for dimensions that can go negative, the weapon/shield mutual-exclusion row); `app/mip-solve.mjs` owns the HiGHS runtime (load, solve, callbacks, no-good cuts, and `gapFromEvents`, the pure absolute-gap formula); `app/exact-solver.mjs` orchestrates one job (the core's heuristic for a fast incumbent, HiGHS for the proof, a hard-floors-conflict retry with every hard floor modelled as soft, optional k-best alternatives via no-good cuts, and always hands the winning suit back to the core for the full report so every result field comes from the same code path). `docs/solver.md` documents the model; `app/bench/mip-spike.mjs` is the spike that led to it, kept as evidence. `app/optimize-worker.mjs` now runs the core's own heuristic (`opts.exact` falsy) or this orchestrator (`opts.exact` true) — one worker per job, since HiGHS explores the tree itself and there is nothing left to split across threads. Progress during the exact phase now carries an incumbent and a bound/gap instead of a bare "explored" fraction; when the WASM fails to load, the job falls back to the heuristic result honestly flagged `solver: "fallback"`, never shown as meeting requirements it didn't check.
- Moved suit-building to a pool per character on the server: `POST /api/optimize` now takes a character name and builds its pools server-side (instead of receiving pools computed in the browser), matching the pools every route already reads from the same fold.
- Added `GET /api/items` — a paged, server-searched and server-sorted item table (`app/item-query.mjs`, the pure filter/sort/page/facet/group logic shared by the browser and the server) plus `GET /api/items/by-serial`, and slimmed `GET /api/inventory` down to facets, worn items and root counts now that the full item table is paged separately.
- Retired the multi-thread branch-and-bound path everywhere it was wired in: `scripts/optimizer-core.ts` no longer takes an `opts.shared`/`OptShared` object or reports `tasks`/`tasksDone` in its progress (the single-thread exact search and dominance pruning stay, as the reference the HiGHS-equivalence tests in `app/solver.test.mjs` compare against); `app/shared-search.mjs` is deleted; `app/bench/run-bench.mjs` no longer escalates a cell to a worker pool once one thread fails to prove it, instead reporting it unproven and running a cheap probe for larger N.
- Added `app/watcher.mts`: one inbox per adapter at `<data>/inbox/<adapter>/`, watched with `fs.watch` and a 300 ms per-filename debounce, normalising an accepted file into `<data>/scans/` under a schema-valid v2 name (idempotent against a stuck duplicate, including across a restart) or, after three failed retries, quarantining it to `<data>/inbox/<adapter>/rejected/` with a reason file beside it. Adapter scripts now write into their inbox instead of straight into `scans/`. Added `GET /api/events` (SSE): a shared stream broadcasting every accept/reject to every connected browser tab, so a scan dropped in game shows up without a manual reload (`app/ui/events.mjs`, with a debounced/coalesced reload for a burst of files).
- Added `app/installer.mts` and the setup-wizard routes it backs: `GET /api/setup` (adapters, candidate client folders, install status), `POST /api/setup/locate`, `POST /api/setup/install` (a running-script guard — 409 while a Legion script looks alive in the client, per the bridge's own `status.json` — then a `.new`-then-rename copy of each script and `packrat-paths.json` written last), `POST /api/import` (copy legacy scans into an adapter's inbox, source never touched), `GET /api/update-check` (GitHub releases, off unless `package.json` names a repo), and `POST /api/host/pick-folder`/`open-path` (folder dialog and open-in-Finder, 501 outside a desktop embedder). `GET|PUT /api/settings` grew `setupDone` and `client` fields.
- Added the first-run setup wizard (`app/ui/wizard.mjs`, four steps: shard — with an AFK-rules notice on shards that need it — client, locate, install) and a Settings tab (`app/ui/settings.mjs`: data/log locations, client status, reinstall, run setup again, import, update check).
- Added the Electron shell (`electron/main.mjs`, `electron/server-entry.mjs`): the server runs as a `utilityProcess` child (so a server crash or a stuck watcher can never take the window down with it) listening on an OS-assigned port; a random per-launch bearer token is set as the child's `VAULT_TOKEN` and attached to every outgoing request to the server's origin via `session.defaultSession.webRequest.onBeforeSendHeaders` — the page itself never sees it. A sandboxed `BrowserWindow` (no preload, `contextIsolation: true`, no `nodeIntegration`) loads the local server; navigation outside its origin is blocked and external links open in the OS browser instead of a second window. Single-instance lock, one automatic restart of a crashed server child, a clean `shutdown` handshake on quit so no `server-entry` process is ever orphaned, and a `--smoke` mode (`scripts/shell-smoke.test.mjs`, `[slow]`, skipped without `electron` installed or with `TEST_SKIP_ELECTRON=1`) that boots the real app, confirms the page rendered, and exits — the automated stand-in for a full end-to-end UI test until Phase 5. `npm run desktop` launches it. Added `docs/architecture.md` describing the process layout, the token flow, the data directory (including the new `inbox/`), the watcher's lifecycle and the installer's guard. Closes Phase 4.
- Renamed the project to **Pack Rat** (the previous name collided with existing UO Alive community tools of the same name): `package.json` name and `productName`, the window/page title, the data directory (now `~/.pack-rat`), the Electron utility-process `serviceName` (now `pack-rat-server`), the GitHub API user-agent string, and the TazUO adapter scripts (now `packrat-{scanner,refresh,bridge}.py`, `packrat-paths.json`, `packrat-paths.example.json`), plus every mention across the docs and tests. Closes Phase 4.5.
